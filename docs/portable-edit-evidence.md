# Portable phone edit package — 4 October 2026

Pre-event research under `prototype/phone-director`, separate from actual Office
Kit integration or an import feature in a desktop editor.

ProjectPackager copies selected ORIGINAL clips into a local ZIP and writes a
`minifilm.portable-edit.v1` project.json plus README. Media paths are autogenerated
and relative, duplicate source URIs are copied once, and original bytes have
SHA-256 hashes. The timeline retains reviewed order/in/out, manual captions,
subtitle provenance and source-to-trimmed-timeline offsets. Provider URIs, shot
IDs, credentials, models and hardware identifiers are omitted from the manifest.
Originals retain embedded metadata and footage outside the selected cut range;
the creator explicitly chooses to save the selected originals and edits.

Bounds are 12 selected cuts / 180 seconds / 512 MiB of total deduplicated
original bytes, enforced while streaming even when a provider omits size. Local
file/content URIs only; remote URL schemes are rejected. Provider MIME determines a safe extension; local file MIME is read from actual
MediaMetadataRetriever metadata rather than guessed from a filename. Unknown
formats keep `.bin`, preserving original bytes. Free-space checks retain
a small reserve. No app network permission, upload or original modification is
part of this workflow. A document provider may itself be cloud-backed: choose
local clips and a local destination when offline use is intended.

Five initial synthetic instrumentation tests passed as part of the combined
20-test/21.065-second run (the one failure was an unrelated recovery fixture
cleanup): real source byte/hash equality, URI dedup, resolvable ZIP paths, cut
ordering/timing, clipped subtitle offsets, unknown-size overflow, revoked source,
cancelled generation suppression, bounds and web-URI rejection. Successfully
returned cache packages survive packager.close for the caller's Files picker.

The app adds an explicit **Save clips + edits for my laptop** action and Android
Files destination picker. Ready-package persistence and background picker deferral
are repaired in source. The six-test package rerun passed, including a blocked
provider read that is cancelled by closing its active stream on a separate
worker, and a late provider open that is closed before any read. Real local MP4
MIME detection and unchanged original bytes are verified. The seven-case UI
rerun encountered the secure locked phone; its screen-dependent failures are
not valid UI evidence. An explicit unlocked-phone precondition now reports
that limitation clearly. Ready-package recreation/visible-only picker behavior
and the actual Files ZIP save still require an unlocked-device rerun. Save interruption can leave a partial chosen
document; the app tells the creator to save again with a new name. Originals stay
intact. Actual Office Kit transfer, received-file hashes and playback remain
unverified. See [Office Kit research](office-kit-research.md) and
[completion audit](completion-audit.md).

Official references: [Storage Access Framework documents/files](https://developer.android.com/training/data-storage/shared/documents-files)
and [ContentResolver](https://developer.android.com/reference/android/content/ContentResolver).
